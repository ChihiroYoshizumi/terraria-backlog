# Backlog 同期

Registry に保存済みの達成に対応する攻略課題を、設定した完了状態へ更新する。

## 背景・目的と利用シナリオ

攻略担当者として、納品や攻略の後に課題を手動更新する手間を減らしたい。通信障害後も保存済み記録から更新をやり直せるようにする。

上位仕様：第8節、第9節。状態：draft。

## 対象・対象外

対象は対応課題の完了更新と再試行。Backlog からゲームへの逆同期、課題の手動完了からの Registry 作成、完了状態の自動取り消しは対象外とする。

## 機能要件・正常時の振る舞い

1. TRAINING_YOSHIZUMI の未完了かつ有効な Mapping を持つ攻略課題と、保存確認済みの Registry を照合する。
2. 対象課題の現在状態を確認する。
3. 既に設定した完了状態なら更新しない。
4. 未完了なら対象プロジェクトの設定済み完了状態へ更新する。

同じ Achievement に対応する複数課題を更新できる。完了状態は表示名や固定値に依存せず、設定を検証して使用する。

初回・定期・手動同期のいずれでも、完了済みの攻略・研修課題は処理対象外とする。状態・本文・属性・コメントを変更せず、達成として取り込まない。照合後に課題が完了した場合も、更新前の状態確認で読み飛ばす。Registry の参照にはこの除外条件を適用しない。

## 例外・境界条件

| 状況 | 期待する扱い |
| --- | --- |
| Registry の保存が未確認 | 課題完了へ進めない |
| 課題が既に完了 | 不要な更新・コメントを追加しない |
| 有効 Mapping の課題を再オープン | 達成済みなら次回同期で再び完了 |
| Mapping を解除 | 以後は更新しない |
| 一部の課題更新だけ失敗 | 保存済み Registry と現行 Mapping を再照合して再試行 |
| 認証・権限・設定のエラー | 診断情報を残し、誤った対象を更新しない |
| 一時エラー・レート制限 | 待機を入れ、API 制約に従って再試行 |

更新応答が不明な場合も、再照合で現在状態を確認する。再試行の根拠を永続的な送信待ちキューに依存させない。

## 関連機能との責務分担

[Mapping](backlog-mapping.md)が対象を定義し、[Registry](achievement-registry.md)が達成を保証する。[Reconciliation](reconciliation.md)が未反映課題を再評価する。納品 ACK は本機能の成否に依存しない。

## 成功基準・受け入れ条件

- AC-10：Registry 保存後に課題更新だけ失敗しても、再同期で完了にできる。
- AC-11との連携：既に完了した課題に不要な更新を繰り返さない。
- AC-14との連携：同一 Achievement に対応する課題をすべて完了できる。
- AC-15との連携：解除された Mapping を次回同期に使わない。
- 課題の手動完了だけでは Registry やワールド状態を変更しない。
- AC-19：既存の完了済み課題へ変更やコメントを行わず、完了済み Registry を参照して未完了の対応課題を同期できる。
