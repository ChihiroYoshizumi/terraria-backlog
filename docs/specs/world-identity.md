# ワールド識別

再起動や名前変更を経ても同じワールドを識別し、別ワールドの達成が混ざることを防ぐ。

## 背景・目的と利用シナリオ

管理者として、複数のワールドに同じ攻略目標を設定しても、それぞれの達成状態を独立して管理したい。

上位仕様：第5.1節、第7節、第10節。状態：draft。

## 対象・対象外

対象は `world_key` の安定性、ワールド間の分離、コピー・巻き戻しの扱い。自動的なワールド同一性推測や履歴の統合は対象外とする。

## 機能要件・正常時の振る舞い

1. ワールド読み込み完了後に識別子を確定する。
2. 採用バージョンで使用可能な固有 ID を使う。利用できない場合は管理者設定の固定 ID を使う。
3. 観測、Registry、Mapping のすべてを同じ `world_key` に結び付ける。
4. Registry と Mapping の照合では Achievement Key と World Key の両方を完全一致で確認する。

ワールド表示名やチェスト座標を識別キーにしない。別ワールドとして運用するコピーには管理者が別キーを割り当てる。

## 例外・境界条件

| 状況 | 期待する扱い |
| --- | --- |
| 再起動・表示名変更 | 同じキーを維持 |
| 異なるワールドに同じ Achievement | 別の達成として管理 |
| ワールドの巻き戻し | 保存済み Registry は取り消さない |
| キーが不明・設定不備 | 対象ワールドの同期を開始せず原因を記録 |
| 未許可ワールドからの通知 | 受理せず、他ワールドのキーへ読み替えない |

## 関連機能との責務分担

[Registry](achievement-registry.md)がキーごとの達成を保存し、[Mapping](backlog-mapping.md)が課題側のワールドを指定する。[運用・セキュリティ](operations-security.md)が通知元と対象ワールドの許可を検証する。

## 成功基準・受け入れ条件

- AC-13：World A の達成があっても、同じ Achievement の未達成 World B の課題は完了しない。
- AC-13：再起動・表示名変更後も同じ Registry を参照できる。
- 別ワールドとして設定したコピーは元のワールドと異なるキーを持つ。
- キーの不備を検出した場合、推測したキーで Registry を作成しない。
