# Reconciliation

現在のワールド状態、Registry、Mapping を照合し、登録・課題反映の不足を補う。

## 背景・目的と利用シナリオ

管理者として、連携サービスの停止や通信失敗から復帰した際に、再取得可能な進捗を反映したい。

上位仕様：第7節、第9節。状態：draft。

## 対象・対象外

対象は起動時・定期・手動の再照合。再取得できない一過性イベント、失われたワールド状態、削除された過去記録の無条件な復元は対象外とする。

## 機能要件・正常時の振る舞い

1. ワールド識別後、Adapter から Boss / World State と納品箱の現在内容を取得する。
2. PHP が同じ機能ルールで達成候補を評価する。
3. Registry の不足を補い、保存結果を確認する。
4. 保存済み Registry と現行 Mapping から攻略課題の不足を補う。

Adapter 起動時だけでなく、PHP のみの再起動後も新しい状態を再取得できること。定期照合はイベント通知や任意の Webhook が届かない場合も機能する。

## 例外・境界条件

| 復旧時に残る根拠 | 補完できる内容 |
| --- | --- |
| 永続的なワールドフラグ | 対象 Boss / World / Event の Registry |
| 納品箱の現存アイテム | Item Registry と保存確認後の ACK |
| Registry と Mapping | 未反映の攻略課題 |
| Registry のみ | 後から Mapping ができた時の課題反映 |
| いずれにも根拠がない | 達成を推測しない |

Backlog が利用できない間は保存成功を断定しない。復旧後に再取得・再検索する。メモリキャッシュを失っても永続キューなしで再構成できる範囲を保証する。

ワールド巻き戻しやチェスト撤去を達成取り消しの契機にしない。Registry 自体の削除・改変は、現在状態で裏付けられる分のみ補完できる。

## 関連機能との責務分担

本機能は再評価の契機と順序を扱う。具体的な達成判定は[納品](collection-chest.md)・[進行](world-progress.md)、保存と課題更新は[Registry](achievement-registry.md)・[同期](backlog-sync.md)の仕様に従う。

## 成功基準・受け入れ条件

- AC-17：保存失敗後に再判定根拠を失った達成を作成しない。
- AC-08・09との連携：残存フラグ・納品から復旧後に Registry を補完できる。
- AC-10との連携：アイテムがもうなくても Registry と Mapping から課題更新を再試行できる。
- PHP のみの再起動でも次の正常な照合で処理が進む。
- AC-18との連携：通信復旧後に再照合が進み、ゲーム処理を待たせない。

## 未決事項・詳細設計への引き継ぎ

- 同期間隔、手動操作、PHP 再起動時の取得契機と通信方向。
- イベント処理との実行調整、タイムアウトと過負荷時の再スキャン方式。
