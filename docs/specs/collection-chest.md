# Collection Chest

指定チェストで確認したアイテムをワールドの取得実績として記録し、保存確認後に取り出せることを通知する。

## 背景・目的と利用シナリオ

プレイヤーとして、共有の納品箱へアイテムを入れるだけで取得を報告したい。登録後は取り出してゲーム内で使用できる。

上位仕様：第5.1節、第6節、第9節。状態：draft。

## 対象・対象外

対象は納品箱の現在内容と登録 ACK。個人 Inventory、取得経路、累積数量、Prefix 別実績、アイテム消費は対象外。取り出しの物理的な禁止は必須としない。

## 機能要件・正常時の振る舞い

1. 名前が設定値と一致するチェストを対象とする。既定値は `BACKLOG_COLLECTION`。
2. Adapter は変更がサーバー状態へ反映された後、現在内容を取得する。
3. PHP は有効な Item ID が存在し、個数が正の場合に `item:<item-id>` を判定する。
4. 攻略課題の有無によらず Registry の保存または既存登録を確認する。
5. 確認したアイテムの登録成功をゲーム内に ACK として表示する。

同名チェストが複数あればすべて対象とする。通常ドラッグ・Shift・Quick Stack・複数スロット更新は同じ現在状態の判定へ収束させる。イベント差分だけで達成を決めず、定期スキャンも行う。

## 例外・境界条件

| 状況 | 期待する扱い |
| --- | --- |
| Registry 保存確認済み | 「登録しました。取り出して OK です」相当の通知 |
| 既存の登録を確認 | 登録済みであることを通知可能 |
| 保存失敗・成否不明 | 成功 ACK を出さず、チェストに残すよう案内 |
| 保存成功、攻略課題更新だけ失敗 | 登録 ACK は可能。課題の反映は再同期 |
| 登録後に取り出す | 達成は維持 |
| 保存前に取り出し、根拠が消失 | 復元を保証しない |
| 改名・撤去 | 過去の記録は維持。未登録分は再確認が必要 |

ACK は課題完了を意味しない。一部アイテムだけ保存できた場合も、未確認のアイテムを成功と表示してはならない。

## 関連機能との責務分担

[Registry](achievement-registry.md)が保存成否を確定し、本機能が表示を担当する。[Reconciliation](reconciliation.md)がイベント取りこぼしや障害後の再スキャンを起動する。

## 成功基準・受け入れ条件

- AC-03：課題のないアイテムも登録され、保存確認後に ACK が表示される。
- AC-04：各操作経路で、最終的な内容から同じ実績を判定できる。
- AC-05：登録後の取り出しで実績や課題が未達成へ戻らない。
- AC-09：Backlog 障害中は成功を通知せず、残存アイテムは復旧後に登録できる。
- AC-12との連携：応答喪失時は既存登録の確認後に ACK を出せる。
- AC-17との連携：再判定根拠が失われた納品は推測して登録しない。

## 未決事項・詳細設計への引き継ぎ

- 各操作経路のフック、反映後の取得タイミング、イベント集約。
- ACK の宛先・アイテムとの相関・再表示方法と通知頻度。
