# Backlog Mapping

攻略課題にワールドと Achievement の対応を保存し、達成前後のどちらでも紐付けられるようにする。

## 背景・目的と利用シナリオ

攻略担当者として、過去の納品後に課題を作っても達成を反映したい。事前の目標登録にも同じ仕組みを使う。

上位仕様：第5.3節、第8節。状態：draft。

## 対象・対象外

対象は Mapping の追加・変更・解除と照合。専用 Mapping テーブル、複数 Achievement の AND / OR 条件、攻略課題の自動生成は対象外とする。

## 機能要件・正常時の振る舞い

1. 攻略課題の `Terraria World Key` と `Terraria Key` 属性へ対応を保存する。
2. PHP が定期照合または手動同期で対応を取得・検証する。
3. Registry に達成があれば課題同期の対象とする。未達成なら課題状態を変えず待つ。

1課題は1ワールドの1 Achievement に対応する。同じ Achievement を複数課題へ紐付けてよい。Backlog 正常時は次の正常な照合サイクルの完了までに後付け Mapping を反映する。

## 例外・境界条件

| 操作・状態 | 期待する扱い |
| --- | --- |
| 登録済み Achievement へ後付け | 再納品・再撃破なしで同期 |
| 未達成への事前登録 | 課題を変更せず達成を待つ |
| 属性を削除 | 以後の同期対象から外す |
| 対応を別 Achievement へ変更 | 新しい対応を評価。以前の完了は戻さない |
| 不正キー・属性欠落・対象外プロジェクト | 更新せず診断情報を残す |
| 対応課題を削除 | Registry を削除しない |
| 同じキーが別ワールドに存在 | 他ワールドの Registry を利用しない |

一覧はページ分割を考慮し、取得したキーを完全一致で確認する。利用者の編集権限は Backlog の権限に従う。

## 関連機能との責務分担

本機能は「どの課題がどの達成に対応するか」を定義する。実際の状態更新は[Backlog 同期](backlog-sync.md)、達成の保存は[Registry](achievement-registry.md)が担当する。

## 成功基準・受け入れ条件

- AC-06：納品記録があれば、取り出し・PHP 再起動後の Mapping 追加でも課題が完了する。
- AC-07：事前 Mapping は未達成時に更新せず、達成保存後に完了する。
- AC-14：同一 Achievement の複数課題を対象にでき、不正な Mapping は更新しない。
- AC-15：解除後の課題を自動更新せず、Registry は残る。
- AC-13との連携：他ワールドの達成で課題を完了しない。

## 未決事項・詳細設計への引き継ぎ

- プロジェクトごとの属性 ID、検索と変更検出方法。
- 手動同期の入口。ゲーム内の Mapping 管理コマンドは採用時に権限を定義する。
