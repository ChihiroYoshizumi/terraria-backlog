# 運用・セキュリティ

Vanilla クライアントで利用できる構成を提供し、連携の権限・秘密情報・障害を管理する。

## 背景・目的と利用シナリオ

管理者として、起動・設定・障害確認の手順を把握し、ゲーム進行への影響と不正な進捗登録を防ぎたい。

上位仕様：第2〜4節、第9〜10節。状態：draft。

## 対象・対象外

対象は起動要件、設定検証、認証・認可、ログ、非ブロッキング動作。具体的なクラウド構成や運用製品の選定は本仕様の対象外とする。

## 機能要件・正常時の振る舞い

| 項目 | 必須の振る舞い |
| --- | --- |
| 接続 | 対応する Vanilla Terraria クライアントが TShock に接続できる |
| 起動 | サーバー・Adapter・PHP Bridge の起動手順またはスクリプトを提供 |
| 保存基盤 | 独自の進捗 DB・永続キューを追加しない。TShock 自身の内部保存は対象外 |
| 設定検証 | バージョン、ワールドキー、対象プロジェクト、属性、完了状態を確認 |
| Backlog 認証 | API Key を PHP 側の環境変数またはアクセス制限した設定に保持 |
| 通信 | Backlog は HTTPS。Adapter → PHP も信頼境界を越える場合は HTTPS |
| 通知の受理 | 認証、送信元と対象ワールドの許可、型・サイズ・キーを検証 |
| 権限 | Backlog は対象プロジェクトに必要な範囲へ限定 |
| 管理操作 | ゲーム内に設ける場合、Mapping 変更・手動同期は管理者のみ |
| 診断 | ワールドキー、処理種別、同期結果、エラー種別を記録 |
| ゲーム影響 | Backlog 通信でゲームのメイン処理を待たせない |

API Key を Git、ログ、課題、ゲーム内チャット、クライアント、Adapter に配布しない。秘密情報を含む URL・ヘッダーや不要なプレイヤー情報も記録しない。

## 例外・境界条件

| 状況 | 期待する扱い |
| --- | --- |
| 未認証・未許可ワールドからの通知 | 拒否し、Registry を作成しない |
| 通知内の任意 URL・プロジェクト | その値に従って外部へ書き込まない |
| 設定不備 | 誤更新を止め、原因を管理者へ表示 |
| 通信遅延・停止 | タイムアウトとメモリ待機量を制限 |
| 混雑で処理を保持できない | 現在状態の再スキャンで補完可能な範囲を復旧 |
| Registry の人手による編集 | 権限を運用上制限し、通常の操作手順に含めない |

## 関連機能との責務分担

[ワールド識別](world-identity.md)・[Mapping](backlog-mapping.md)の入力を守り、[Reconciliation](reconciliation.md)の再実行に必要な設定・診断手段を提供する。再判定不能な進捗の復元保証は追加しない。

## 成功基準・受け入れ条件

- AC-01：MOD なしの対応クライアントで納品と進捗同期を利用できる。
- AC-16：未認証・対象外ワールドの通知を拒否し、API Key がログ・チャットに出ない。
- AC-18：Backlog 遅延・停止時もゲーム進行をブロックせず、復旧後に照合が進む。
- AC-02との連携：アプリ専用 DB・永続キューを用意せずに起動できる。
- 設定不備で更新を止めた理由を管理者が確認できる。

## 未決事項・詳細設計への引き継ぎ

- 対応バージョン、PHP フレームワーク、配置と起動方式。
- 認証方式、秘密情報の配置・更新手順、許可対象の設定。
- タイムアウト・待機量の上限とゲーム影響の測定方法。
- ログ出力先と、診断・手動同期の具体的な操作手順。
