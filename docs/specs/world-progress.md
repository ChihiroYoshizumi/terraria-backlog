# World Progress

Boss 撃破やワールド進行を、現在の永続的なワールド状態から判定して記録する。

## 背景・目的と利用シナリオ

参加者として、連携処理が停止している間の攻略進行も、再開後に現在状態から反映してほしい。

上位仕様：第2節、第5.1節、第7節。状態：draft。

## 対象・対象外

対象は再判定可能な Boss・World・Event のフラグ。撃破回数、個人の戦績、永続フラグのない一過性イベントは対象外とする。

## 機能要件・正常時の振る舞い

1. Adapter がイベントを契機に現在のワールド状態を取得する。
2. PHP が対応表を使い、再判定可能な達成を評価する。
3. 確認できた Achievement を Registry に登録する。
4. 起動時・定期・手動の照合でも同じ判定を使う。

| 種別 | 対象の方針 |
| --- | --- |
| World | `world:hardmode` |
| Boss | 下記候補から、採用バージョンで永続状態との対応を確認したもの |
| Event | 永続フラグにより達成を再判定できるもののみ |

Boss 候補は Eye of Cthulhu、Skeletron、Wall of Flesh、The Destroyer、The Twins、Skeletron Prime、Plantera、Golem、Lunatic Cultist、Moon Lord。候補の列挙は対応確認済みを意味しない。

## 例外・境界条件

| 状況 | 期待する扱い |
| --- | --- |
| Adapter 停止中に進行し、状態が保存されている | 復帰後の照合で補完 |
| 共有フラグしかなく個別撃破を区別できない | 個別撃破を推測しない |
| 永続フラグがない | MVP の復旧対象に含めない |
| クラッシュで未保存状態が失われた | 消失した達成を復元しない |
| 巻き戻しでフラグが戻った | 登録済み Registry は取り消さない |

C# は状態を取得して転送する。どの状態をどの Achievement と扱うかは PHP 側の責務とする。

## 関連機能との責務分担

[ワールド識別](world-identity.md)が観測の帰属を定め、[Registry](achievement-registry.md)が達成を保存する。[Reconciliation](reconciliation.md)が再評価の契機を管理する。

## 成功基準・受け入れ条件

- AC-08：停止中の進行が保存されていれば、起動時に対象フラグから補完できる。
- 対象フラグが成立していなければ、その Achievement を登録しない。
- 識別不能な候補は理由を明示し、イベント履歴ストアを追加して救済しない。
- AC-17との連携：現在状態にも Registry にも根拠のない達成は作成しない。
